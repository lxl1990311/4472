### cs-draft.html —《CS 大乱斗 / GOAT DRAFT》
- 单文件 HTML，零依赖，双击即玩，localStorage 存生涯最佳。
- 玩法：5 个位置（狙击/突破/指挥/辅助/自由人）各抽 3 张卡选 1 张，共 5 轮，然后出评分。
- 选手池约 48 名真实 CS 选手，rating 用生涯巅峰近似值（1.04–1.37）。
- 化学反应系统（核心设计，也是分数差异的真正来源）：
  - 同队 ×2/+3、×3/+7、×4/+11、×5/+16
  - 同国（避开同队重复计算）net≥1 → +2/+3
  - 同时代（年代跨度≤3）+3；跨度≥6「时代错位」-3
  - 激进风格 ≥3 人 → -3 风格冲突
  - 指挥评分 ≥1.16 → +3「指挥有权威」，≥1.08 → +1，低于 → -2
- 评分公式：`score = 42 + (avg - 1.24) * 160 + chem * 1.5`
  其中 avg = Σ(rating × 位置权重 × 位置契合度) / 5
- 段位：S+ 92 / S 86 / A 79 / B 69 / C 57（门槛以此为准，改公式需同步改门槛）

## 第三次改造：对齐真实机制（22:00 用户发截图）

用户发了「82胜」实际界面截图，机制与此前猜测完全不同：

**真实机制**：
- 抽的不是球员，是「**战队 + 年代**」（截图：「老鹰 / 20s 年代」）
- 抽出后从该队该年代全部球员里挑 1 人，填进仍空闲的位置
- 每签有 **1 次**「更换球队 / 更换年代」重抽机会（二选一）
- 共 5 签，对应 5 个位置（PG/SG/SF/PF/C → CS 的 awp/entry/igl/support/lurker）
- 球员有档次标签（全明星）和可打位置标注，位置被占后其他人变灰不可用
- 球员之间有羁绊

**据此重做 cs-draft.html**：
- 数据结构从「位置池」改为 `SQUADS = {战队: {年代: [选手]}}`
- 12 支战队 × 24 套阵容 × 135 条选手记录，每套阵容保证五位置齐全
- 选手字段：`{n:ID, p:[位置...], r:rating, c:国籍}`
- 新流程：`drawSquad(keepTeam,keepEra)` → `renderSign` → `pickInto(pl,pos)`
- 抽签自动过滤"无人可用"的阵容，避免卡死（3000 局测试 0 次卡死）
- 位置契合改为按 `p` 数组下标：`p[0]` 本职 1.0，之后 0.93 / 0.70

**羁绊体系（适配抽签机制后重调）**：
- 同队 ×2 **+5**（从 +3 上调，因为抽签制下同队更难），×3 +9，×4 +13，×5 +18
- 同国 net≥1 → +2/+3；同时代跨度≤3 → +3；时代错位跨度≥6 → −3
- **巨星过多（≥4 个传奇档）−4**，三核 +1（替代原来的"风格冲突"，因为 tags 字段已删）
- 指挥权威按 rating 阈值：≥1.16 +3，≥1.08 +1，否则 −2

**关键发现：avg 分布被压缩到 1.26~1.45**（此前是 1.27~1.49），
因为每个位置只能从当前抽到的那批人里挑，个人分被平均掉了。
→ **化学反应成了唯一有效的分数轴**，权重必须拉到 `chem * 2.0`。
最终公式：`score = 62 + (avg - 1.30) * 130 + chem * 2.0`
（跑过三轮调参：base 42→56→62，chem 系数 1.5→2.0）

**校准后（3000 局）**：
| 策略 | 平均分 | S+ | S | A | B | C | D | 平均冠军 |
|---|---|---|---|---|---|---|---|---|
| 随机选人 | 69.2 | 1.4% | 4.3% | 15.6% | 38.1% | 32.1% | 8.6% | — |
| 贪心选（每次挑最高 rating） | 76.3 | 4.2% | 10.9% | 32.9% | 37.7% | 13.9% | 0.4% | 1.87 |

段位门槛同步改为：S+ 94 / S 86 / A 77 / B 67 / C 57。

**设计上的宿命**：这个机制下"抽到什么队"比"选谁"影响更大，
真正的决策点收窄到**那 1 次重抽用在哪儿**——换队凑羁绊，还是换年代赌更强的阵容。
这是机制自带的，不是 bug。

- 核心加成逻辑（`coreBonus`，范围 −8 ~ +8）：
  - 队内最强 → +4「核心名副其实」；第二强 +1；第三 −2；最弱 −5
  - 位置修正：IGL 当核心 +2，Support 当核心 −2
- 界面：`.coregrid` 竖排卡，选中高亮，未选时按钮禁用

**新增：战术体系（第 2 / 2 步）**
- 12 个战术，3×3 网格 + 3 个未解锁（教练体系 / 数据分析 / 心理战）

- **契合度算法（扬长避短）**：
  ```
  tacBonus = Σ (该球员rating − 队内平均rating) × (位置乘数 − 1) × 70
  ```
  含义：被强化的位置上如果有强人 → 加分；最强的位置被削弱 → 扣分。
  范围 −14 ~ +14，`tacBonus` 直接加到总分。

**分数公式（第 4 版，最终）**：
```
score = 58 + (avg − 1.30) × 130 + chem × 2.0 + tacBonus + coreBonus
```
base 从 62 降到 58 —— 因为"选最强的人当核心"多数时候是对的，会让整体上移 4 分。

**校准（2500 局，贪心选人 + 核心选最强）**：

→ **选对战术值 2.7 分 / 0.46 个冠军**，量级合适：不是决定性，但值得动脑。

## 第八次改造：单位置直放 + HLTV TOP20 定档（22:51 用户反馈）

**1. 只剩一个空位时点人名直接入位**
`selectPlayer()` 开头判断 `openPos(pl).length === 1`，是则直接 `pickInto(opens[0])` 并 return。
多空位时仍走"选中 → 点亮槽位 → 点槽"两步。

**2. 档次改用 HLTV 年度 TOP20 排名定档**（用户质疑 rating 来源）
此前 `tierOf(r)` 只看估算的 rating，无权威依据。现在：

```js
function tierOf(r, t20){
  if(t20){
    if(t20 <= 3)  return 'legend';   // 年度前三
    if(t20 <= 10) return 'star';     // 年度前十
    return 'pro';                    // 入榜前二十
  }
  // 无榜单数据的年份才退回 rating 估
  if(r>=1.26) return 'legend';
  if(r>=1.20) return 'star';
  if(r>=1.12) return 'pro';
  return 'solid';
}
```

**T20 数据（已联网查证）**：2018 / 2019 / 2020 / 2021 / 2022 / 2023 / 2024 共 7 年完整榜单。
**缺**：2014 / 2015 / 2016 / 2025（这四年的阵容共 26 条记录，仍按 rating 估）。

覆盖率：135 条里 49 条有 TOP20 排名（36%）。
**这不是缺陷**——每年只有 20 个名额，135 条记录里大部分人本来就没进过榜。
档次分布 legend 8 / star 28 / pro 55 / solid 44，8 个传奇全部来自 TOP20 前三，没有漏判。

`t20Of(pl, era)` 按「年份 + 选手 ID」查表，因为同一个人不同年份排名差很多：
- device：2018 #2（传奇）→ 2020 #3（传奇）→ 2021 #11（一线）→ 2023 #11
- s1mple：2018 #1 → 2022 #1 → 2023 #7
- b1t：2021 #9 → 2024 #9

卡片标签现在显示 `传奇 #1` / `巨星 #8` 这种形式，让依据直接可见。
