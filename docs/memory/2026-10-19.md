### 严重 bug：单年代队伍整页空白（用户截图发现）
- 现象：抽到 Falcons 2026（或任何「该队仅 1 个年代」的队）时，球员卡与阵容条全不渲染。
- 根因：渲染模板在单年代队时输出的是 `<button class="rb" disabled>`（无 id），
  但事件绑定里直接写 `$('rbEra').onclick = ...` → null.onclick 抛 TypeError →
  后面的 `renderPlayerList()` 与 `renderLineup()` 全被跳过。
- 测试为什么没抓到：旧 DOM 桩对**任何 id 都返回假元素**，`$('rbEra')` 永远非 null，
  属于假绿灯。这类 bug 只有真实 DOM 或严格桩才能暴露。
- 修法三点：
  1) `const rbEra = $('rbEra'); if(rbEra) rbEra.onclick = ...`；
  2) `renderLineup()` 提到 innerHTML 赋值之后、事件绑定之前，任何后续异常都不再影响阵容条；
  3) 阵容条位置回归 bug 一并修正——挪回 `.draft` 最上方（bar 之下、抽签面板之上）。
- 新测试方法：写严格 DOM 桩，`getElementById` 只返回 HTML 中真实出现过的 id，其余返回 null。
  结果：61 套全部渲染正常（每套 5 卡 + 5 槽），25 局完整流程 0 异常。
  **以后 UI 回归一律用严格桩，不再用"万能假元素"。**

### 核心评语自相矛盾（用户发现）
- 现象：选队内最强当核心，结算页却写「核心的选择有问题：队内最强，核心名副其实。」
- 根因：`if(Math.abs(r.coreBonus) >= 3)` 把 **+4 的正向加成也当成"有问题"**，绝对值用错。
- 修法：拆成正负两支
  - `coreBonus >= 4` → 「核心选对了。{note}。」
  - `coreBonus <= -3` → 「核心的选择有问题：{note}。」
- 同时清理文案：删除自我循环的「核心名副其实」；去掉 note 中间句号造成的「。。」；
  避免「核心的选择有问题：核心是…」重复主语；辅助改为「队里未必服」。
- 验证：最强/次强/指挥/辅助/最弱 五种选择逐条检查，无「正向报有问题」「双句号」「重复核心」。
